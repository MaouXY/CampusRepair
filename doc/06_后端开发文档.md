# 后端开发文档

## 一、后端目标

后端基于 Spring Boot 实现校园智能报修服务平台的业务接口，负责用户认证、角色权限、工单流转、文件上传、RustFS 对象存储、AI 辅助分析、RAG 知识库检索、统计分析和数据大屏聚合数据。

后端设计重点：

- 保证报修、派单、处理、评价的完整闭环。
- 保证学生、维修人员、管理员的数据权限隔离。
- 保证 AI、RAG、RustFS 等外部依赖异常时主流程可控。
- 凡是 catch、兜底、降级、第三方调用失败，都必须写应用运行日志。

## 二、技术栈

| 类型 | 技术 | 说明 |
| --- | --- | --- |
| 基础框架 | Spring Boot | RESTful API 和业务服务 |
| 数据库 | MySQL | 持久化业务数据 |
| ORM | MyBatis Plus / MyBatis | 数据访问层 |
| 权限认证 | JWT / Sa-Token / Spring Security | 三类角色权限控制 |
| 对象存储 | RustFS | 报修图片、维修结果图片 |
| AI 编排 | LangChain4j | 大模型调用、提示词、RAG |
| 向量检索 | LangChain4j EmbeddingStore / 数据库向量索引 | 知识库和历史工单检索 |
| 日志 | SLF4J + Logback | 运行日志和异常堆栈 |
| 接口文档 | Knife4j / Swagger | 前后端联调 |

## 四、核心模块

### 1. 认证与权限模块

功能：

- 登录、退出、当前用户信息。
- Token 签发、刷新和校验。
- 角色权限控制：`STUDENT`、`WORKER`、`ADMIN`。
- 数据范围控制：学生只能看自己的工单，维修人员只能看分配给自己的工单，管理员可管理全部工单。

核心接口：

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/auth/login` | POST | 登录 |
| `/api/auth/logout` | POST | 退出 |
| `/api/auth/me` | GET | 当前用户信息 |

### 2. 工单模块

功能：

- 学生提交报修。
- 工单审核、驳回、取消。
- 管理员派单。
- 维修人员接单、处理中、提交结果。
- 学生确认和评价。
- 工单状态流转记录。

状态枚举：

| 状态 | 说明 |
| --- | --- |
| `PENDING_REVIEW` | 待审核 |
| `ASSIGNED` | 已派单 |
| `ACCEPTED` | 已接单 |
| `PROCESSING` | 处理中 |
| `WAITING_CONFIRM` | 待确认 |
| `COMPLETED` | 已完成 |
| `CANCELLED` | 已取消 |
| `REJECTED` | 已驳回 |

开发要求：

- 状态流转必须集中校验，不允许接口随意修改状态。
- 每次状态变更写入 `repair_ticket_flow`。
- 派单、接单、提交结果等关键操作必须校验当前用户权限。

### 3. RustFS 文件模块

功能：

- 上传报修图片。
- 上传维修结果图片。
- 保存对象 key、访问地址、文件名、文件大小、文件类型。

核心接口：

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/files/upload` | POST | 通用文件上传 |
| `/api/files/{id}` | GET | 文件元数据 |

开发要求：

- 限制文件类型和大小。
- 上传成功后再写数据库记录。
- RustFS 连接失败、上传失败、删除失败必须写应用运行日志，日志包含业务场景、用户 ID、工单 ID、文件名和完整异常栈。

### 4. AI 辅助模块

功能：

- 故障分类。
- 优先级判断。
- 工单摘要生成。
- 相似工单推荐。
- AI 调用记录。
- 关键词规则兜底。

核心接口：

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/student/ai/precheck` | POST | 报修前 AI 预分析 |
| `/api/admin/ai-logs` | GET | AI 调用记录查询 |

开发要求：

- LangChain4j 调用失败不能影响报修提交。
- AI 分析结果必须以 JSON 格式输出，优先启用模型侧 JSON mode 或等价能力限制输出形态。
- prompt 必须声明输出 schema、必填字段、枚举范围和禁止额外字段，不能只写“请输出 JSON”。
- 模型返回必须经过服务端 JSON 解析、DTO 反序列化和业务字段校验。
- 首次解析或校验失败时，最多触发一次 repair 二次修复；修复仍失败才走关键词规则兜底。
- 模型异常、超时、JSON 解析失败、schema 校验失败、repair 失败、兜底分支必须写运行日志。
- 记录 AI 结构化输出指标，如解析失败次数、校验失败次数、repair 成功率和兜底次数。
- `ai_call_log` 只用于业务留痕，不能替代运行日志。

### 5. RAG 知识库模块

功能：

- 管理维修知识库。
- 文本切片。
- 生成 Embedding。
- 建立向量索引。
- 根据用户问题检索相关知识片段。
- 基于检索结果调用大模型生成回答。

核心接口：

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/student/ai/knowledge-answer` | POST | RAG 知识库问答 |
| `/api/admin/knowledge` | GET/POST/PUT/DELETE | 知识库管理 |
| `/api/admin/knowledge/rebuild-index` | POST | 重建向量索引 |

开发要求：

- RAG 回答必须返回来源，如 `knowledgeItemId`、`ticketId`、`noticeId`。
- 检索为空时不能让大模型编造答案。
- 高风险问题优先返回安全提示和紧急报修建议。
- RAG 检索失败、索引重建失败必须写运行日志。

### 6. 统计与数据大屏模块

功能：

- 报修总量统计。
- 今日新增、待处理、超时工单统计。
- 分类占比。
- 地点热度。
- 平均处理时长。
- 维修人员工作量排行。
- 评价满意度。

核心接口：

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/admin/stats/overview` | GET | 统计概览 |
| `/api/admin/stats/screen` | GET | 数据大屏聚合指标 |

开发要求：

- 列表查询必须分页。
- 统计接口支持时间范围筛选。
- 大屏接口返回聚合后的 DTO，避免前端重复计算复杂数据。

## 五、数据库开发要求

如涉及数据库建表、改表、添加测试数据，必须写入 SQL 文件，并告诉用户执行顺序，由用户执行。

建议 SQL 文件顺序：

1. `sql/01_schema_base.sql`：用户、角色、地点、分类等基础表。
2. `sql/02_schema_ticket.sql`：工单、图片、流转、评价、派单表。
3. `sql/03_schema_ai_rag.sql`：AI 调用记录、知识库、知识片段、向量索引映射表。
4. `sql/04_seed_data.sql`：演示账号、分类、地点、知识库、测试工单。

## 六、统一日志要求

以下场景必须写应用运行日志：

- 捕获异常的 `catch`。
- 兜底返回。
- 降级分支。
- RustFS 调用失败。
- LangChain4j 调用失败。
- RAG 检索失败或索引重建失败。
- 派单失败、状态流转失败、权限异常。

日志至少包含：

- 业务场景。
- 关键上下文 ID，如 `ticketId`、`studentId`、`workerId`、`knowledgeItemId`、`aiCallLogId`。
- 真实异常信息。
- 未预期异常或第三方依赖失败优先使用 `log.error(..., exception)` 保留完整堆栈。

## 七、后端开发顺序

1. 初始化 Spring Boot 项目、统一返回、异常处理、日志配置。
2. 建表 SQL 和基础测试数据。
3. 用户认证与角色权限。
4. 工单主流程：提交、审核、派单、接单、处理、评价。
5. RustFS 文件上传。
6. 分类、地点、维修人员管理。
7. LangChain4j AI 预分析。
8. RAG 知识库和向量索引。
9. 统计分析和数据大屏接口。
10. 接口文档、测试用例和演示数据补齐。
