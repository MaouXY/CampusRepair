# 前端开发文档

## 一、前端目标

前端基于 Vue 实现学生 Web 门户、维修 Web 工作台、管理员后台和数据大屏。前端不做移动端、小程序或 uni-app，所有角色均通过浏览器访问。

前端设计重点：

- 学生报修流程清晰，减少填写成本。
- 维修人员能快速查看待处理任务。
- 管理员能高效审核、派单、配置基础数据。
- 数据大屏突出关键运营指标。
- AI 和 RAG 结果只作为建议展示，必须允许人工修改或忽略。

## 二、技术栈

| 类型 | 技术 | 说明 |
| --- | --- | --- |
| 框架 | Vue 3 | 前端主体 |
| 构建工具 | Vite | 开发和构建 |
| UI 组件 | Element Plus | 表单、表格、弹窗、分页 |
| 状态管理 | Pinia | 用户信息、权限、基础字典 |
| 路由 | Vue Router | 角色路由和页面跳转 |
| 图表 | ECharts | 统计图表和数据大屏 |
| 请求 | Axios | API 调用和拦截器 |

## 四、页面规划

### 1. 登录页

功能：

- 账号密码登录。
- 根据角色进入不同首页。
- 保存 Token 和当前用户信息。

### 2. 学生 Web 门户

页面：

| 页面 | 功能 |
| --- | --- |
| 学生首页 | 展示我的报修概览、公告、快捷报修入口 |
| 提交报修 | 填写地点、描述、上传图片、AI 预分析 |
| AI 预分析结果 | 展示建议分类、优先级、摘要、相似工单 |
| 我的工单 | 查看报修列表和状态 |
| 工单详情 | 查看流转记录、维修结果、图片 |
| 维修评价 | 对已完成工单评分和评价 |
| RAG 自助问答 | 输入问题，查看知识库建议和来源 |

交互要求：

- AI 推荐内容必须可编辑或可忽略。
- 相似工单只做提示，不阻止用户继续提交。
- 图片上传需要显示进度、成功状态和失败提示。
- RAG 回答需要展示来源，不能只显示一段模型回答。

### 3. 维修 Web 工作台

页面：

| 页面 | 功能 |
| --- | --- |
| 维修首页 | 待接单、处理中、今日完成概览 |
| 我的工单 | 按状态筛选工单 |
| 工单详情 | 查看报修信息、图片、AI 摘要、流转记录 |
| 接单处理 | 接单、更新状态、填写处理结果 |
| 历史记录 | 查看个人历史维修工单 |

交互要求：

- 关键操作需要二次确认，如接单、完成。
- 处理结果必须支持文字说明和图片上传。
- 工单状态变化后刷新详情和列表。

### 4. 管理员后台

页面：

| 页面 | 功能 |
| --- | --- |
| 工作台 | 待审核、待派单、超时工单、今日新增 |
| 工单管理 | 查询、审核、驳回、修改分类和优先级 |
| 派单管理 | 分配维修人员或部门 |
| 分类管理 | 维护维修分类和关键词 |
| 地点管理 | 维护楼栋、教室、实验室等地点 |
| 维修人员管理 | 维护人员、部门、可处理分类 |
| 公告管理 | 发布停水停电、维修通知 |
| 知识库管理 | 维护 RAG 知识条目 |
| AI 调用记录 | 查看模型结果、兜底状态、异常信息 |
| 统计分析 | 图表展示报修量、时长、满意度 |

交互要求：

- 管理员审核时可以修改 AI 分类、优先级和摘要。
- 知识库修改后提供“重建向量索引”按钮。
- AI 调用记录页要区分成功、失败、兜底、RAG 召回为空。

### 5. 数据大屏

页面内容：

- 工单总数。
- 今日新增。
- 待处理数量。
- 超时工单数量。
- 分类占比环图。
- 地点热度排行。
- 近 7 日报修趋势。
- 维修人员工作量排行。
- 平均处理时长。
- 满意度统计。

实现要求：

- 使用 ECharts。
- 页面适合大屏展示，减少复杂表单。
- 数据来自 `/api/admin/stats/screen`。
- 支持定时刷新，例如 60 秒刷新一次。

## 六、前端权限控制

- 路由守卫检查 Token。
- 根据用户角色生成可访问菜单。
- 前端隐藏无权限入口，后端仍必须做最终权限校验。
- Token 过期时清空登录状态并跳转登录页。

## 七、接口调用约定

统一响应格式建议：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

分页响应建议：

```json
{
  "records": [],
  "total": 0,
  "pageNum": 1,
  "pageSize": 10
}
```

前端处理要求：

- 请求拦截器统一携带 Token。
- 响应拦截器统一处理登录失效和错误提示。
- 上传接口单独处理进度和文件大小限制。
- AI/RAG 接口失败时提示“智能建议暂不可用，不影响提交报修”。

## 八、前端开发顺序

1. 初始化 Vue 项目、路由、Pinia、Axios、Element Plus。
2. 登录页和基础布局。
3. 学生端：提交报修、我的工单、工单详情。
4. 维修端：我的工单、接单处理、结果填写。
5. 管理端：工单审核、派单、分类、人员、地点。
6. RustFS 文件上传组件联调。
7. AI 预分析结果展示。
8. RAG 自助问答和知识库管理。
9. 统计分析和数据大屏。
10. 权限、空状态、错误状态、加载状态和演示数据打磨。
