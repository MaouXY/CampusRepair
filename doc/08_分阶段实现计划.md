# 分阶段实现计划

## 一、实现原则

项目按“先闭环、再智能、后优化”的顺序实现。第一阶段先保证报修业务能跑通，第二阶段补齐管理和权限，第三阶段接入 RustFS、LangChain4j 和 RAG，最后做统计、大屏、测试和论文材料。

如涉及数据库建表、改表或测试数据，必须写入 SQL 文件，并说明执行顺序，由用户执行。

## 二、阶段划分

| 阶段 | 目标 | 核心产出 |
| --- | --- | --- |
| 第 0 阶段 | 项目初始化 | 前后端骨架、代码规范、基础配置 |
| 第 1 阶段 | 数据库和基础能力 | SQL 文件、统一返回、认证权限 |
| 第 2 阶段 | 工单主流程闭环 | 学生报修、管理员审核派单、维修处理、学生评价 |
| 第 3 阶段 | 基础管理能力 | 分类、地点、人员、公告管理 |
| 第 4 阶段 | RustFS 文件能力 | 报修图片和维修结果图片上传 |
| 第 5 阶段 | AI 辅助能力 | LangChain4j 分类、摘要、优先级、规则兜底 |
| 第 6 阶段 | RAG 知识库能力 | 知识库管理、向量索引、检索增强问答 |
| 第 7 阶段 | 统计和数据大屏 | 统计分析、大屏展示、图表 |
| 第 8 阶段 | 测试和论文支撑 | 测试数据、截图、测试报告、答辩材料 |

## 三、详细计划

### 第 0 阶段：项目初始化

后端任务：

- 创建 Spring Boot 项目。
- 配置 MySQL、MyBatis Plus、日志、接口文档。
- 定义统一返回对象、分页对象、全局异常处理。

前端任务：

- 创建 Vue 3 + Vite 项目。
- 接入 Element Plus、Pinia、Vue Router、Axios、ECharts。
- 完成登录页、基础布局、菜单框架。

验收标准：

- 前后端项目可启动。
- 前端能访问登录页。
- 后端接口文档可访问。

### 第 1 阶段：数据库和基础能力

后端任务：

- 编写基础建表 SQL。
- 编写测试账号和基础字典 SQL。
- 实现登录、当前用户、角色权限。
- 实现用户、角色、地点、分类基础查询。

前端任务：

- 登录联调。
- 当前用户信息展示。
- 路由守卫和菜单权限。

SQL 执行顺序：

1. `sql/01_schema_base.sql`
2. `sql/04_seed_data.sql`

验收标准：

- 三类账号可以登录。
- 不同角色进入不同首页。
- 无权限页面无法访问。

### 第 2 阶段：工单主流程闭环

后端任务：

- 工单创建。
- 工单列表和详情。
- 管理员审核、驳回、派单。
- 维修人员接单、处理中、提交处理结果。
- 学生确认和评价。
- 工单流转记录。

前端任务：

- 学生提交报修页。
- 学生我的工单和详情页。
- 管理员工单审核和派单页。
- 维修人员工单列表和处理页。
- 学生评价页。

SQL 执行顺序：

1. `sql/02_schema_ticket.sql`
2. `sql/04_seed_data.sql`

验收标准：

- 一条工单可以从提交流转到完成。
- 每次状态变化都有流转记录。
- 学生、维修人员、管理员权限隔离正确。

### 第 3 阶段：基础管理能力

后端任务：

- 分类管理。
- 地点管理。
- 维修人员管理。
- 公告管理。

前端任务：

- 分类管理页面。
- 地点管理页面。
- 维修人员管理页面。
- 公告管理页面。

验收标准：

- 管理员可维护基础数据。
- 学生报修时可选择地点和分类。
- 公告可在学生端展示。

### 第 4 阶段：RustFS 文件能力

后端任务：

- 接入 RustFS。
- 实现文件上传接口。
- 保存文件元数据。
- 工单图片和维修结果图片关联。

前端任务：

- 封装图片上传组件。
- 学生提交报修时上传图片。
- 维修人员提交结果时上传图片。
- 工单详情展示图片。

验收标准：

- 图片可上传到 RustFS。
- 数据库保存对象 key 和访问地址。
- RustFS 上传失败时有明确错误提示和运行日志。

### 第 5 阶段：AI 辅助能力

后端任务：

- 接入 LangChain4j。
- 实现分类、摘要、优先级判断。
- 启用 JSON mode 或等价能力，约束 AI 分析结果以 JSON object 输出。
- 在 prompt 中声明输出 schema、必填字段、枚举范围和禁止额外字段。
- 实现模型结果 JSON 解析、DTO 反序列化和业务字段校验。
- 实现 repair 二次修复，修复失败后再进入规则兜底。
- 实现关键词规则兜底。
- 写入 AI 调用记录。
- 记录解析失败、校验失败、repair 和 fallback 指标及运行日志。

前端任务：

- 提交报修页调用 AI 预分析。
- 展示建议分类、优先级、摘要。
- 管理员审核时可修改 AI 建议。
- AI 不可用时提示不影响报修提交。

验收标准：

- 输入故障描述后能返回 AI 建议。
- AI 建议结果必须是服务端校验通过后的 JSON DTO。
- AI 返回非 JSON、字段缺失或枚举非法时能触发 repair；repair 失败时走规则兜底。
- AI 失败时走规则兜底。
- 兜底和异常均有运行日志。

### 第 6 阶段：RAG 知识库能力

后端任务：

- 知识库 CRUD。
- 知识条目切片。
- 生成 Embedding。
- 建立向量索引。
- 实现 RAG 问答接口。
- 实现向量索引重建接口。

前端任务：

- 学生端 RAG 自助问答页。
- 管理端知识库管理页。
- 管理端重建索引按钮。
- 展示 RAG 回答来源。

SQL 执行顺序：

1. `sql/03_schema_ai_rag.sql`
2. `sql/04_seed_data.sql`

验收标准：

- 学生输入问题后返回基于知识库的回答。
- 回答显示来源。
- 检索为空时不编造答案。
- RAG 检索失败和索引重建失败有运行日志。

### 第 7 阶段：统计和数据大屏

后端任务：

- 统计总览接口。
- 数据大屏聚合接口。
- 报修趋势、分类占比、地点热度、人员工作量统计。

前端任务：

- 管理端统计分析页。
- 数据大屏页面。
- ECharts 图表封装。
- 大屏定时刷新。

验收标准：

- 管理员可查看统计分析。
- 数据大屏可展示核心指标。
- 图表数据与工单数据一致。

### 第 8 阶段：测试和论文支撑

后端任务：

- 补齐核心接口测试。
- 准备演示数据。
- 检查日志覆盖。
- 整理接口文档。

前端任务：

- 补齐空状态、加载状态、错误提示。
- 准备演示截图。
- 检查页面跳转和权限。

论文和答辩材料：

- 系统截图。
- 数据库表说明。
- 核心流程图。
- AI/RAG 说明。
- 测试用例和测试结果。

验收标准：

- 演示流程稳定。
- 答辩问题有对应材料。
- 文档、代码、SQL 和测试数据一致。

## 四、推荐开发优先级

必须优先完成：

- 登录和权限。
- 工单主流程。
- 管理员审核派单。
- 维修人员处理。
- 学生评价。
- RustFS 上传。
- AI 预分析和规则兜底。

然后完成：

- RAG 知识库问答。
- 统计分析。
- 数据大屏。
- 公告管理。
- AI 调用记录。

最后优化：

- 相似工单推荐。
- AI 命中率统计。
- 更细的数据筛选。
- 页面视觉和演示体验。
