# 检索质量调优与语料导入管道

> 本文对应两项工作：**A. 检索质量三改**（召回阈值 + 只重排前 N + RRF×rerank 加权融合）与 **B. 语料导入管道**（PDF/Word/规范 → 清洗 → 章节切分 → 元数据入库 → 向量同步）。

## A. 检索质量三改：让 RRF 与 rerank 不再互相抵消

### A.1 原来的问题

原流程是「关键词召回 + 向量召回 → RRF 融合 → rerank 覆盖排序」。设计上两阶段并不冲突（RRF 解决异构分数不可比与召回不全，rerank 解决排序不准），但实现上有三处会互相抵消：

| 问题 | 后果 |
| --- | --- |
| 向量召回 `minScore=0.0`，RRF 又只看名次 | 向量库里相似度极低的片段只要排在向量列表第 1，也能拿到与完美匹配相同的满权重 |
| rerank 用 `relevance_score` **完全覆盖** RRF 排序 | 「关键词+向量双路都命中」的共识信号被丢弃，低质片段可能把共识片段压下去 |
| RRF 分数（≈1/61≈0.016）与 rerank 分数（0~1）量纲差两个数量级 | 一旦想做加权混合，不归一化就等于废掉 RRF |

### A.2 现在的实现

```text
① 关键词召回：min-keyword-hits 过滤（默认 1，可提到 2 降噪）
② 向量召回：Milvus minScore = min-vector-score（默认 0.25）
③ RRF 融合：score = Σ weight/(60+rank)，取候选池
④ 只对前 N 条（rerank-window，默认 20）送 cross-encoder 重排
⑤ 加权融合：final = α·norm(rerank) + (1-α)·norm(rrf)，α = rerank-blend-weight（默认 0.7）
   重排未生效（未开启/缺 Key/调用失败）→ α 自动为 0，退回纯 RRF 顺序
⑥ 窗口之外（第 N+1 条起）保持 RRF 顺序追加，最终截取 limit
```

要点：

- **归一化**：窗口内 RRF 分与 rerank 分各自做 min-max 归一化后再加权；同分时回退 RRF 顺序（tie-break）。
- **窗口限制**：重排 API 只处理前 N 条，`top_n` 传窗口大小（保证窗口内每条都有分数，不会因 `top_n=6` 让其余候选拿 0 分而集体沉底），既省钱又保留长尾的 RRF 排序。
- **降级链**：rerank 任何异常都不会影响出结果，`RagSearchResult.rerankSkipReason` 会记录 `disabled / missing-api-key / empty-scores / call-failed`。

### A.3 配置

```yaml
app:
  agent:
    rag:
      hybrid:
        enabled: true
        rrf-k: 60
        keyword-top-k: 10
        vector-top-k: 10
        keyword-weight: 1.0
        vector-weight: 1.0
      ranking:
        min-vector-score: ${APP_RAG_MIN_VECTOR_SCORE:0.25}      # 过低则噪声占位，过高则召回骤降
        min-keyword-hits: ${APP_RAG_MIN_KEYWORD_HITS:1}         # 提到 2 可显著降噪
        rerank-window: ${APP_RAG_RERANK_WINDOW:20}              # 只重排 RRF 前 20 条
        rerank-blend-weight: ${APP_RAG_RERANK_BLEND_WEIGHT:0.7} # α：1.0=纯重排，0=纯 RRF
```

`GET /api/v1/admin/rag/vector-status` 会把这 4 个参数与 Embedding/向量库状态一起返回，前端已展示，便于现场核对与演示。

### A.4 如何做消融实验（论文素材）

用 RAG 评测模块固定评测集与 TopK，逐项改动并记录指标：

| 实验 | 设置 | 观察指标 |
| --- | --- | --- |
| E1 基线 | `hybrid.enabled=false`（纯关键词） | HitRate / Recall / MRR / nDCG |
| E2 混合 | `hybrid.enabled=true`，其余默认 | 对比 E1 看 RRF 增益 |
| E3 阈值 | `min-vector-score` 取 0 / 0.25 / 0.4 | 看噪声过滤与召回损失的平衡点 |
| E4 融合权重 | `rerank-blend-weight` 取 0 / 0.3 / 0.7 / 1.0 | 看 RRF 共识与重排信号的最优配比 |
| E5 窗口 | `rerank-window` 取 6 / 20 | 看精排覆盖范围对指标与成本的影响 |

## B. 语料导入管道：把规范/手册变成可检索知识

### B.1 为什么不能直接扔进向量库

规范手册是**条文式结构**：按固定 800 字硬切会把一条条文切成两半，检索到半句话既无法引用也不利于模型理解。所以要「先清洗、再按章节切、最后给每片带上章节标题」。

### B.2 两条入口

| 入口 | 适用场景 | 接口 |
| --- | --- | --- |
| 整篇导入 | 页面上直接粘贴原文（txt/md 内容、手工整理稿） | `POST /api/v1/admin/rag/corpus/import`（先 `POST /corpus/preview` 预览切分） |
| 批量导入 | PDF/Word 已由脚本转成 JSONL，一条记录 = 一个章节 | `POST /api/v1/admin/rag/corpus/import-batch` |

### B.3 清洗与切分规则（后端 `RagCorpusSplitter`）

清洗：

1. 统一换行、全角空格转半角、去零宽字符；
2. 去页码行（`12`、`- 12 -`、`第 12 页`）；
3. 去页眉页脚：同一短行（<40 字）出现 ≥3 次且不是标题 → 删除；
4. **合并硬换行**：上一行不以 `。；：！？）》”` 结尾且当前行不是标题 → 拼接为一段（`标题行永不与下一行合并`，否则章节识别会失效）；
5. 压缩空行。

章节识别与切分：

1. 识别 `第X章/节/条`、`一、`、`（一）`、`1.1`、`附录A` 等标题行（行长 ≤ 40 字才算标题，避免误判正文编号句）；
2. 标题行若「编号 + 正文」同行（如 `第一条 为规范…`），只取编号部分作标题，**其余正文仍保留**，不丢内容；
3. 子章节标题自动带上级章名：`第二章 空调设备维护 / 2.1 滤网清洗`，检索命中后引用更准确；
4. 超长章节（>1500 字）按自然段二次切分，带重叠（默认 120 字），每片仍以 `【章节】标题` 开头。

### B.4 元数据

新增 `sql/19_schema_rag_corpus_metadata.sql`：

- `rag_knowledge_document`：`source`（来源）、`standard_no`（标准号/文号）、`doc_version`、`effective_date`、`doc_type`（standard/manual/policy/case）、`import_batch`（导入批次）；
- `rag_knowledge_chunk`：`section_title`（所属章节，便于「标准号 + 章节」回引）。

批量导入按 `standardNo|title` 分组：同一条规范的多章节会合并成**一份知识文档**，章节信息落在切片上。

### B.5 文档转换脚本 `tools/corpus/convert_corpus.py`

用法（详见 `tools/corpus/README.md`）：

```bash
# PDF / Word / txt / md 批量转换，输出可直接导入的 JSONL
python tools/corpus/convert_corpus.py --input docs/ --output corpus.jsonl \
  --source "GB 55022-2021" --standard-no "GB 55022-2021" --doc-type standard \
  --doc-version 2021 --effective-date 2021-04-09 --category-id 20001
```

- **零依赖**：`.txt/.md` 与 `.docx`（标准库 zipfile + XML 解析，含页眉页脚）；
- **PDF 三级兜底**：`pypdf` → `pdfminer.six` → 本机 **Word COM** 另存为 txt（无需 pip）；
- 输出字段与后端 `CorpusSectionItem` 完全对齐，含自测脚本（`sample/selfcheck.py`，91 项断言）。

### B.6 语料来源建议（按优先级）

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 1 | **自家工单沉淀** | 已完成闭环的工单经审核入库，零领域偏差、许可自有，已由 V3 的草稿流程自动化 |
| 2 | 国家标准/行业规范 | 如 GB 55022-2021《既有建筑维护与改造通用规范》、TSG T5002-2017《电梯维护保养规则》等，条文式最适合本管道；内部引用需注明标准号与版本 |
| 3 | 设备说明书/厂家维保手册 | 空调、投影仪、饮水机、洗衣机、门禁的排查步骤来源 |
| 4 | 校内制度文件 | 报修流程、响应时限、消防设备维护通知等「流程类」问答 |
| 5 | 公开技术资料 | 仅内部参考，建议改写为自有表述以规避版权 |

> 注意：BEIR / T2Ranking / DuReader / RGB / CRUD-RAG 等公开数据集是**评测集**（query + qrels），其语料多为新闻/网页片段，**不适合**当校园维修知识库；评测与语料要分开建设。
