# 演示环境整体迁移到另一台电脑

> 把本机这套「校园报修」完整搬到另一台机器：**MySQL（业务数据）+ RustFS（图片）+ Milvus（向量）**，
> 外加后端/前端的配置检查。三件套缺一不可：缺 MySQL 什么都打不开、缺 RustFS 工单图片 404、缺向量 AI 检索失效。

| 组件 | 内容 | 位置/参数 |
| --- | --- | --- |
| MySQL | 33 条工单、14 篇知识文档、191 切片、4 条知识草稿、54 条评测用例、9 个账号 | `127.0.0.1:3306`，库 `campus_repair`，root/1829002 |
| RustFS | 桶 `campus-repair`：**39 个对象 / 3.8 MiB**（报修图、结果图） | S3 API `127.0.0.1:9990`，控制台 `9991`，`rustfsadmin`/`rustfsadmin` |
| Milvus | 集合 `campus_repair_knowledge`：**191 条**（dim 2560 / COSINE） | `127.0.0.1:19530`（gRPC 与 REST v2 同端口） |

## 1. MySQL

```powershell
# 源机导出（全库，含业务数据与文件元数据）
& 'C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe' --host=127.0.0.1 --user=root --password=1829002 `
  --default-character-set=utf8mb4 --single-transaction --databases campus_repair `
  --result-file=$env:TEMP\campus_repair.sql

# 目标机建库并导入（把 sql 拷过去）
mysql --host=127.0.0.1 --user=root --password=<目标库密码> --default-character-set=utf8mb4 < campus_repair.sql
```
注意：`file_metadata.public_url` 里存的是**完整 URL**（`http://127.0.0.1:9990/campus-repair/...`），
若目标机存储地址/端口不同，导入后批量替换：
```sql
UPDATE file_metadata SET public_url = REPLACE(public_url, 'http://127.0.0.1:9990', 'http://新地址:9990');
```

## 2. RustFS（对象存储）：**必须按桶逻辑迁移，不能拷磁盘目录**

原因：两台机器的卷布局可能不同，磁盘格式不通用。本机实测对比：

| | 源机 | 目标机（示例） |
| --- | --- | --- |
| 目录 | `pro\rustfs0 ~ rustfs3` + `.rustfs.sys` | `data\.rustfs.sys` + `campus-repair` |
| 配置 | `RUSTFS_VOLUMES=/data/rustfs{0..3}`（4 卷纠删码，对象被切成数据片/校验片散落各卷） | `RUSTFS_VOLUMES=/data`（单卷直存） |
| 结论 | — | **目录不能直接拷**（格式不同，读不出来） |

用脚本一条命令完成（自动下 mc、建桶、镜像对象、搬桶策略、对比两端数量）：

```powershell
pwsh tools/rustfs-migrate.ps1 -TargetEndpoint http://<目标机IP>:9990 -DryRun   # 先看统计
pwsh tools/rustfs-migrate.ps1 -TargetEndpoint http://<目标机IP>:9990           # 正式迁移
```

- 目标机 9990 若从本机不可达：在**目标机**上跑同样脚本，把 `-SourceEndpoint` 填本机 IP（方向反过来）。
- 桶策略：源桶是 `custom`（允许匿名 `s3:GetObject`/`ListBucket`），**mirror 不会带策略**，脚本第 5 步会 `anonymous get-json/set-json` 搬过去；漏了它图片会 403。
- 磁盘目录搬迁仅在**两边卷布局完全一致**时才可行（需停机、且必须整目录四个卷一起拷）。

## 3. Milvus（向量）

```powershell
# 目标机（已建好 Milvus，版本需 ≥ 2.4）
powershell -NoProfile -ExecutionPolicy Bypass -File .\milvus-import.ps1 `
  -Source .\milvus-campus_repair_knowledge.jsonl `
  -Collection campus_repair_knowledge -CreateCollection
# 目标端已有集合时，也可用 Attu「导入数据」+ attu-milvus-*.json（JSON 数组格式）
```
校验：`count(*) = 191`，维度 2560；embedding 模型与源机一致（`doubao-embedding-text-240715`）。

## 4. 目标机配置检查（后端 `application.yaml`）

| 配置 | 期望 |
| --- | --- |
| `spring.datasource.url` | 目标机 MySQL 地址/库 `campus_repair` |
| `app.agent.rag.milvus.uri` | 目标机 Milvus `http://<host>:19530` |
| `app.agent.rag.milvus.collection-name` | `campus_repair_knowledge`（与源一致） |
| `app.storage.rustfs.endpoint` | 目标机 `http://<host>:9990` |
| `app.storage.rustfs.bucket` / `base-path` | 均为 `campus-repair`（必须与对象 key 前缀一致） |
| `app.storage.rustfs.access-key/secret-key` | 目标机 RustFS 的密钥（默认 `rustfsadmin`/`rustfsadmin`） |
| Ark / Bocha 密钥 | 可用同一账号；否则 AI 与重排会降级（功能仍在） |
