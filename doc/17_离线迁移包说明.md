# 校园报修系统 · 离线迁移包（目标机操作说明）

> 两台机器**不通网**（无公网 IP、不同局域网），所以用 U 盘 / 微信文件传输 / 网盘把这个包搬过去，
> 在目标机上按下面 5 步执行即可。**全程不需要联网**（`mc.exe` 已附带）。

## 包内容

| 目录/文件 | 内容 | 大小 |
| --- | --- | --- |
| `mc.exe` | S3 对象存储客户端（Windows 版，已附，免下载） | 30 MB |
| `rustfs\s3\campus-repair\...` | 报修图/结果图 **39 个对象**（按对象 key 原样落盘） | 3.8 MB |
| `rustfs\bucket-policy.json` | 桶访问策略（允许匿名读，图片才能直接显示） | 0.4 KB |
| `mysql\campus_repair.sql` | 全库导出：33 条工单、14 知识文档、191 切片、4 草稿、54 评测用例、9 账号、文件元数据 | 1.15 MB |
| `milvus\milvus-campus_repair_knowledge.jsonl` | 向量导出（191 条，含 `__schema` 头，脚本导入用） | 4.39 MB |
| `milvus\attu-milvus-campus_repair_knowledge.json` | 同数据转成 JSON 数组（Attu「导入数据」用） | 4.39 MB |
| `milvus\*.ps1` | 导入/导出/格式转换脚本 | — |

**前置条件**：目标机已装 Docker，且 MySQL、Milvus（≥2.4）、RustFS 三个容器已启动；
项目代码可从 GitHub 克隆（`git clone https://github.com/MaouXY/CampusRepair.git`）或直接拷贝整个目录。

## 第 1 步：导入 MySQL

```powershell
mysql --host=127.0.0.1 --port=3306 --user=root --password=<目标库密码> `
      --default-character-set=utf8mb4 < .\mysql\campus_repair.sql
```
校验：`SELECT COUNT(*) FROM repair_ticket;` → 应为 **33**。

> 好消息：两台机器本地都用 `127.0.0.1:9990`，所以 `file_metadata.public_url` 里存的历史图片 URL
> **不需要改**，导入后图片可直接显示。（若目标机存储端口不同才需要 `REPLACE` 批量替换。）

## 第 2 步：导入 RustFS 对象（务必用 mc，不能拷磁盘目录）

> 原因：两台机器的 RustFS 卷布局不同（源机是 `rustfs0~3` 四卷纠删码，目标机是单卷直存），
> 磁盘格式不通用，只能按对象做逻辑导入。

```powershell
cd <解压后的包目录>\rustfs

# 配置目标别名（RustFS 默认账号密码，若你改过请替换）
..\mc.exe alias set dst http://127.0.0.1:9990 rustfsadmin rustfsadmin

# 建桶（已存在会报 "already exists"，忽略即可）
..\mc.exe mb dst/campus-repair

# 灌入对象（--preserve 保留时间戳；本地 s3 目录下的相对路径就是对象 key）
..\mc.exe mirror --preserve .\s3 dst/campus-repair

# 应用桶访问策略（漏了这步图片会 403）
..\mc.exe anonymous set-json .\bucket-policy.json dst/campus-repair

# 校验：应显示 Total Objects: 39   Total Size: 3.82 MiB
..\mc.exe ls --recursive --summarize dst/campus-repair
```

最后在浏览器里直接打开一张图片 URL 验证返回 200：
`http://127.0.0.1:9990/campus-repair/campus-repair/student/2026-09-11/10001/<某个文件名>`

## 第 3 步：导入 Milvus 向量（二选一）

**方式 A：脚本（推荐，自动建集合+索引+校验）**
```powershell
cd <包目录>\milvus
powershell -NoProfile -ExecutionPolicy Bypass -File .\milvus-import.ps1 `
  -Source .\milvus-campus_repair_knowledge.jsonl `
  -Collection campus_repair_knowledge -CreateCollection
# 结束会打印 count(*)，应为 191
```

**方式 B：Attu 图形界面**
1. 先建集合（字段必须 4 个，少一个都会报 `some field does not exist`）：
   `id` VarChar(36) 主键且**关闭自动ID**、`text` VarChar(65535)、`metadata` **JSON**、`vector` FloatVector(**2560**)
   一致性 Bounded，不启用动态Schema
2. 建索引：AUTOINDEX + **COSINE**，索引名 `vector`
3. 加载集合 → 「导入数据」→ 选 `attu-milvus-campus_repair_knowledge.json`

校验：`curl.exe -s -X POST http://127.0.0.1:19530/v2/vectordb/entities/query -H "Content-Type: application/json" -d '{\"collectionName\":\"campus_repair_knowledge\",\"filter\":\"\",\"outputFields\":[\"count(*)\"]}'` → `191`

## 常见问题

| 现象 | 原因/处理 |
| --- | --- |
| `mc` 报证书/连接错误 | 确认 endpoint 用 `http://`（不是 https）、端口 9990 是 RustFS 的 S3 端口 |
| 图片 403 | 桶策略没应用 → 重跑 `anonymous set-json` |
| 图片 404 | 对象没灌进去（`mc ls --recursive` 看数量）或桶名/base-path 与配置不一致 |
| Attu 导入报 `some field does not exist` | 集合少字段（常见漏 `text`/`metadata`），删掉重建或用第 3 步方式 A |
| 向量条数不是 191 | 维度填错（必须 2560）或集合非空导致重复 |
| 工单列表打不开/报 500 | MySQL 没导入或库名不对 |
